# Deploying to Render

`render.yaml` is a Render Blueprint. The build command installs the backend
requirements and builds the frontend (`cd frontend && npm ci && npm run build`);
FastAPI then serves `frontend/out`. `NODE_VERSION=22` is pinned in `render.yaml`.

## Stop committing the build output (owner action)

Once a Render deploy with the new build command is confirmed working:

```sh
git rm -r --cached frontend/out
echo "frontend/out/" >> .gitignore
git commit -m "Stop tracking frontend/out (built on deploy)"
```

Do not do this before the first successful Render build, or the deploy has no frontend.
(`frontend/.gitignore` already ignores `/out/`, but the directory was committed before that.)

## Database (Neon)

Render's disk is ephemeral; without `JYOTISH_DATABASE_URL` the app uses SQLite
on local disk and every deploy/restart wipes all accounts.

1. Create a project at https://neon.tech (pick a region near the Render region).
2. Copy the pooled connection string (`postgresql://user:pass@host/db?sslmode=require`).
3. In Render, set `JYOTISH_DATABASE_URL` to it. Tables are created on startup.

## Environment variables

| Variable | Required | Notes |
|---|---|---|
| `JYOTISH_ENV` | yes | `prod` (set in render.yaml); enforces the JWT secret rules |
| `JYOTISH_DATABASE_URL` | yes | Neon Postgres URL (see above) |
| `JYOTISH_JWT_SECRET` | yes | Auto-generated by Render; must be >= 32 bytes. Rotating it logs everyone out |
| `JYOTISH_LLM_PROVIDER` | yes | `gemini` (render.yaml), or `groq`, `openrouter`, `ollama`, `lmstudio`, `offline` |
| `JYOTISH_LLM_EXTERNAL_CONSENT` | yes for external LLMs | Server-level switch (`true`); users accept AI processing in the required service terms at signup (existing accounts accept the updated terms once) |
| `GEMINI_API_KEY` | if provider gemini | Set in dashboard |
| `GROQ_API_KEY` | optional | Fallback provider |
| `OPENROUTER_API_KEY` | optional | Free-model fallback |
| `JYOTISH_SMTP_HOST`, `JYOTISH_SMTP_PORT`, `JYOTISH_SMTP_USER`, `JYOTISH_SMTP_PASSWORD`, `JYOTISH_SMTP_FROM` | optional | Outgoing email (e.g. password reset). Without them email features are disabled |
| `JYOTISH_PUBLIC_BASE_URL` | with SMTP | Public site URL (e.g. `https://jyotish-ai.onrender.com`), used to build links in emails |
| `SENTRY_DSN` | optional | Error tracking |
| `NODE_VERSION` | build | `22` |

Other tunables (defaults are fine): `JYOTISH_JWT_EXPIRE_HOURS`, `JYOTISH_*_MODEL`,
`JYOTISH_LLM_TURN_DEADLINE`, `JYOTISH_LLM_MAX_CONCURRENCY`, `JYOTISH_CHAT_RATE_LIMIT`,
`JYOTISH_FRONTEND_ORIGIN` (CORS, only if the frontend is hosted elsewhere).

Note: SMTP variables and email features are documented per the planned design;
verify the names against `backend/app` once that code lands.

## Free plan

The free web service sleeps after ~15 minutes idle; the first request afterwards
takes tens of seconds (cold start). Use a paid instance for real users. The
health check is `/api/health`.

## End-to-end tests

```sh
cd frontend
NEXT_PUBLIC_API_URL= npm run build    # same-origin API base
npx playwright install chromium
npm run e2e                           # E2E_PORT=8011 to change the port (default 8001)
```
